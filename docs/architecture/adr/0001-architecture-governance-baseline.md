# ADR 0001：架构治理基线与边界

日期：2026-11-28

## 状态

已接受，作为本轮治理的工作约束。

## 背景

仓库当前形态已经不是“原生 Android 应用 + 多个实验方案”，而是一个明确产品：Android WebView 宿主内嵌官方 OpenCode UI，页面直连 OpenCode v2 服务，宿主提供系统能力。历史演进留下了并行实现、事故编号绊线、手写源码与生成产物混放、入口层上帝对象和文档副本漂移。

## 决策

1. 以当前真实产品形态为重构目标，不恢复旧原生壳、旧 gateway 或 Ghostty 终端路线。
2. `frontend/android/upstream.json` 是上游 UI 版本唯一权威来源；`webapp/build.gradle.kts` 是 Android 版本和包名唯一权威来源。
3. `webapp/src/main/assets/www/ui/` 与 `oc-terminal.js` 是生成产物。生成产物可以提交，但必须能由唯一源码重建并被 CI 校验。
4. Android 宿主入口层可以编排能力模块；能力模块不得反向依赖入口具体类。
5. 删除死代码优先于增加兼容层。只有在存在真实调用方、外部契约或明确产品兼容承诺时才保留兼容实现。
6. 行为验证优先于源码字符串绊线。确实不能行为化的资产约束可以保留，但必须集中、命名清晰并不阻碍死代码删除。

## 约束

- 不改变 APK applicationId、签名证书、versionCode/versionName 的发布语义。
- 不改变 OpenCode v2 服务协议、服务器浏览器 RPC 的外部兼容语义或用户本地存储数据含义。
- 不手改上游 UI 生成产物；上游行为变化只能通过 pin、patch、覆盖源码和构建脚本。
- 本机签名按 `AGENTS.md` 使用用户指定密钥，凭据只传给本次构建进程。

## 后果

正向：后续重构有明确边界，删除历史实现不再需要保留“也许有一天恢复”的平行路线。

代价：部分历史绊线会被删除或改写。必须用更强的行为验证替代，而不是简单删除保护。
