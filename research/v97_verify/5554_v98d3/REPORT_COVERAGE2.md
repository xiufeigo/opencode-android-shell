### 3.3 机理解释

```
第 1 次：host='ssh -p 2222 sshtest@127.0.0.1'  name='E2ECHK5554d3c-01'
         → 点 Add server → 【静默失败】：不关表单、不弹口令、无红字、无新行
第 2 次：表单仍保留第 1 次的值 → 新输入被【追加】在后面 → host 变成非法拼接串
         → 必然更建不成
第 3/4 次：同理，脏值越滚越长
```

> ⇒ **「凑不满 4 行」的完整因果链**：
> `Add server` 首次提交即被拒绝（条目 0 条）
> → 表单**不 reset** → 后续每次重试都在脏值后追加
> → 从第 2 次起连输入都不合法 → 永远建不成第 2 条
> → 列表始终停在「他人那 2 条」→ **第 3/4 行根本无从构造**。

**这同时解释了上一轮的两个观察**，它们不是自动化抖动，是同一个机制的产物：
- 「表单已预填残留（host/name/passphrase 有值、keypath 为空并报红字）」= 表单从不 reset；
- 条目名被污染成 `127.0.0.1E2ECHK5554d3c-02` = 脏值被拼接后**居然落库过一次**
  （说明该构建下 submit 并非恒定失败，至少偶尔能过 —— 上一轮因此拿到了真实条目）。
