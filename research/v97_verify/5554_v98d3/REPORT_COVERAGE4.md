### 2.4 ★★ 三个「关不掉软键盘」的死角（本轮耗时最长的部分，如实记录）

`Add server` 的可点祖先在面板基准位是 `y∈[1736,1862]`，
**而软键盘弹出后会盖住这一段** ⇒ **键盘不关，`Add server` 就点不到**。
按纪律不能用 BACK(4)、弹层内不能用 ESC(111)，本轮逐个试过：

| 关闭手段 | 结果 |
|---|---|
| 点 `Host or SSH command` 标签 | ❌ `mInputShown` 仍 = `true` |
| 点表单标题 `Add SSH server` | ❌ 仍 = `true` |
| 点 `Server name (optional)` 标签 | ❌ 仍 = `true` |
| 点表单卡空白右边距 `(1020, 1368)` | ❌ 仍 = `true` |
| `keyevent 61` (TAB) | ❌ 仍 = `true`，且**焦点不移动** |
| `keyevent 20` (DPAD_DOWN) | ⚠️ 仍 = `true`，但**焦点会移动**（见下） |
| `keyevent 19` (DPAD_UP) | ❌ 仍 = `true` |
| `keyevent 66` (ENTER) | ❌ 仍 = `true` |

**⇒ 本轮的正解不是"关键盘"，而是"绕开键盘"**：

1. 点 host 框 → 打字；
2. **`keyevent 20`（DPAD_DOWN）把焦点移到 name 框**，Compose 的 `bringIntoView`
   随即把 name 框滚进可视区（实测 `[138,1246][943,1372]`，h=126 满高）；
3. **name 框此时已是焦点，直接 `input text` 打字，不需要再点它**（点了会因它在键盘下方而失败）；
4. `Add server` 在**滚动后的位置**（`[723,1340][975,1466]`）**恰好在键盘上方，仍可点**。

> **诚实边界**：DPAD_DOWN 只在 **name 框已可见**时才移焦点。
> 若 name 框被裁成 6px 残片，DPAD_DOWN **焦点不动**，名字会被打进 host 框。
> 本轮两种情况都实测到了（见 §3.2 的污染证据）。

## 5. 本轮的方法论修正（给下一轮的硬前置，替换第三轮的 5 条）

### 5.1 ★ 定位字段：**锚在表单的内层 `ScrollView` 上，不要用绝对 y 窗口**

第三轮前置 #2「别用 `Authentication` 标签的 y 当锚点」**不够** ——
本轮实测**表单滚到底时连 `Host or SSH command` 标签本身都不在 a11y 树里**。
正解：`ScrollView` 里**包住 EditText 的那个**（内层表单 body）⇒ 字段窗口随之浮动。

### 5.2 ★ 关不掉软键盘 ⇒ 不要关，要绕开（§2.4 的完整表）

DPAD_DOWN 移焦点 + 焦点框直接打字 + 键盘上方点 `Add server`。

### 5.3 ★ 清字段：**`keyevent 123`（MOVE_END）+ N 次 DEL(67)**，不要用裸 DEL 循环

裸 DEL 从光标**向前**删；光标在中间时会留下尾巴。
本轮实测污染：`ssh -p 2222 sshtest@127.0.0.1` → **`ssh -p 2222 sshtest@127.0.0.10.0.1e`**。
更稳的是**关闭重开表单**（第三轮已证 `remember` 状态离开组合即丢弃）。

### 5.4 ★ 解析 dump 的两个 PowerShell 陷阱

1. `FindN 'X' 0` 取的是**第一个**匹配 —— 面板标题和表单标题**都叫 `Add SSH server`**；
   弹层出现时**表单的 `Cancel` 会排在口令卡的 `Cancel` 前面** ⇒
   本轮因此误点表单 `Cancel` 关闭了表单。**必须按 bounds 或按所属容器区分同名节点。**
2. **返回单元素数组会被 PowerShell 拆成标量** ⇒ `$l[0][1]` 抛
   "无法将值转换为类型 System.Object[]"。**必须 `@(FormETs)` 显式包一层。**

### 5.5 ★ 计数时要把**表单里的 EditText** 排除

`SELF_COUNT` 曾经把**打开的表单输入框**（内容含前缀）当成一行统计 ⇒ 虚高一。
**计数只认行容器里的 kebab（`Server actions`）。**
