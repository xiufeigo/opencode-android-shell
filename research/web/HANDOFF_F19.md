## 1. 新增的那一节：§0.5「手机形态：走一遍旅程才发现的两条缺陷，已经闭环」

### 1.1 为什么这一节最重要

**此前所有验证都在平板档做**（V8 / V12 / F11–F15），**手机档的整条主链从未被走完过**。而这两条缺陷 —— 恰恰是**在平板上"看起来完全正常"**的：平板没有状态栏层，也没人测 BACK。

### 1.2 发现方式（本节第一段就写清）

| 维度 | 写法 |
|---|---|
| 形态 | 手机档 ≈ **360dp**（`wm size 1080x2340` + `wm density 480` ⇒ `1080/(480/160)=360dp`；回读 `innerW=360/innerH=780/dpr=3`） |
| 怎么走 | **像用户那样按顺序走完整条链**：冷启动 → 会话列表 → 进会话 → **真点发送** → 等回复 → 滚动 → 开面板 → 切会话 → **按 BACK 返回**（10 步） |
| **不走什么** | **不做单项机制测试**。不单独去测"inset 算没算出来"、"BACK 顺序对不对" —— **这两样当时都自认为是对的** |
| 被测物 | **最可能分发的 R8 包** |

### 1.3 缺陷 A：顶部压状态栏时钟 / 穿过挖孔

- **根因＝两处各断一半**（本节最该记住的一点）：
  - ① **宿主侧根本没投递 inset** —— `InsetsHost.kt:72-74` + `:145`，`init` 里 `requestApplyInsets()` 在 Activity onCreate 阶段就触发首次 `publish`，此时页面尚未加载 ⇒ **决定性实测 `getInsets()` 返回 `null`**；`:145` 的去重让这条**静态**读数永不重发。
  - ② **页面侧也没消费** —— 上游不认 `--oc-safe-top`，而 `env(safe-area-inset-top)` 因 WebView 边到边**恒为 0**。
  - **运行时反证**：手动触发 `refresh()` 后 `getInsets()` **仍是 `null`** ⇒ 不是"值没算出来"，是"**算出来了但送不到 + 送到了也没人用**"。
- **改前读数**：左区 `20-92` **合并**、中区 `48-88` **穿挖孔**、**净空 0 px**。
- **改后读数**：左区 `20-49`（仅时钟）/ `114-161`（标题）**分离**、中区 `48-59` **仅挖孔条**、**重叠 0 px / 净空 64 px（≈21 dp）**。
- **几何自洽性**：标题带起点 114 px **严格大于** `safeTop` 折算像素（`24 dp × dpr 3 = 72 px`）⇒ 既不重叠，**也没有把标题压在安全区里**。
- **修法**：① 宿主加 `replay()`（**不去重地**补发），由 `onPageFinished` 调用；② 页面注入 `oc-top-inset`，用 `--oc-safe-top-eff = max(--oc-safe-top, env(safe-area-inset-top))` 给**根容器**垫 `padding-top`（垫根容器而非 `header`，因 `#root` 是 `h-dvh` + `border-box`，垫后总高仍是视口高、不溢出）。
- **✅ 平板 1280×800 回归仍 `overlapPx=0`、三栏完整**（`innerH=800` 未被压塌）。

### 1.4 缺陷 B：面板打开时 BACK 误退

- **根因＝宿主里 BACK 顺序写反**：`canGoBack()` 排在页面 `onBack()` **前面**；而上游 SPA **用 History API 站内导航** ⇒ **进会话时已压历史** ⇒ 实测 `histLen=2` ⇒ `canGoBack()==true` ⇒ **面板开着也被弹掉**，页面 `onBack()` 根本没被问到。
  - **与最初猜想不同**：**不是"没历史可退"，是"有历史且被优先消费了"**。
- **改后**：
  - **1×BACK** ＝ `pageHandled=true (overlay closed), no history pop` ⇒ **面板关、仍停会话**（Tab 条/标题/历史/composer 全部完好）；
  - **2×BACK** ＝ `pageHandled=false -> goBack()` + `GET /api/session?limit=5000` ⇒ **才回会话列表**；
  - 历史深度：改前**一次退两级** → 改后**一次一级，粒度正确**。
- 一并写进了 F18 自己的澄清：**与本仓铁律"绝不按 BACK(4) 关面板"不冲突**（那条针对**测试脚本拿 BACK 当关闭手段**；用户真按 BACK 时期望就是先关浮层。**脚本关面板仍应点 `≡`**）。

### 1.5 V14 重走结果

**10/10 PASS**（V13 是 9 PASS + 1 FAIL；**第 10 步"返回/后退"由 FAIL 转 PASS**）· 冷启动 **659 ms** · 真点发送 `POST /prompt` **`code=200`**（upstream **12 ms**）· 回复 **5 s**，**无 ANR、无白屏** · **未观察到新问题**（5 项逐一复查正常）· 平板档 spot check 正常（**补上了 F18 自认的未闭环项**）。

**取证方法值得一提**：R8 包**无 CDP** ⇒ F18 那些 DOM 读数在 R8 上复现不了。V14 改用**两条不依赖 CDP 的独立证据链**：**截图像素级几何**（证明缺陷 A）+ **logcat 宿主回执**（证明缺陷 B）。**结论一致，取证路径不同** —— 这是**面向最终交付的 R8 包**的直接证据。

### 3.4 UX2 的终端「杀 app 回来自动接回同一会话」（这就是本轮重建交付物的理由）

**一句话**：`LoopbackProxy` 原来绑 `ServerSocket(0)`（**系统临时端口**）⇒ 页面 origin
`http://127.0.0.1:<随机端口>` **每次启动都变** ⇒ `localStorage` 按 origin 隔离 ⇒
**上游已经存在的"持久化 pty id + 进终端页自动 attach"根本读不到** ⇒ 回来只能是空终端。
本轮把端口**钉在 40495**（新增 `host/StableOrigin.kt`，被占时自动退回临时端口、不会起不来），
让 origin 跨启动不变，**上游那套机制原样生效**。
详见 `research/web/UX2_TERMINAL_REATTACH.md`。

**下轮必读的三条**：

1. **没有新增任何持久化、没碰凭据** —— 本轮**没有**在宿主侧存 pty id，
   复用上游 `localStorage` 里那一份（`session/terminal/context.tsx:104`）。
   `StableOrigin` 里只有一个端口号，`F21` 的口令闸门与 `LaunchGuard` 调用点**一行未动**。
2. **端口钉住是"尽力而为"** —— 40495 被占时会**静默退回临时端口**（= 退化回改前行为）。
   若下轮发现"又接不上了"，**先看 logcat 里 `home=http://127.0.0.1:<port>` 的 port 是不是 40495**。
3. **服务端没有 idle 回收** —— 只有显式 `DELETE`（`pty.remove`）和进程退出两条 kill 路径
   （`core/src/pty.ts:115-132`）⇒ "等超时回收"这一格**测不出来**，
   详见报告 §6（如实记为未实测 + 原因）。
