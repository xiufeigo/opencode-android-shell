## 5. 追加的 2 条教训（§6.1 ⑯⑰）

**⑯「轮次结束但脚本还在跑」会同时毁掉两样东西：报告和设备。**
F14 轮起了两回合常亮循环，**轮次在脚本还在跑的时候就结束了** ⇒ ① **报告根本没写出来**；② **留下一个自建模拟器还开着**（违反 §6.3「谁起谁关」）。半份产物只能按 git 提交信息如实登记（`wip(web): partial output from the cleanup round…`），4 条保持未闭环，由 F15 重做并闭环。
**⇒ 纪律（三条，F15 就是照这三条做的）**：**边做边写盘**（每步追加落盘，不攒到最后）· **不许长脚本空等**（每步单独执行 + 单独取证）· **收尾无论成败先关实例**（按 AVD 名 + 端口确认是自己的 → `emu kill` → 抄复核输出）。**报告没写成事小，设备没关是持续伤害别人的资源。**

**⑰「标签不能代替事实」—— 自己起的变量名/段名也会骗自己。**
F13 的 `SEG0_idle` **标签写着 `idle`（空闲基线），实际却落在「回合已开始后 0.2 s」** ⇒ 若照标签解读，会得出"flag 一直就 true"或"空闲态也置旗"这类**与事实相反**的结论。F15 重采（tap **前 3 ms 纯读取**）才真正闭环。
**⇒ 纪律**：**命名必须与实际采样时刻绑定**；关键段要能用**同一次执行里相邻的两条带时间戳日志**自证先后（F15 用 `11:44:43.229` < `11:44:43.285`，差 3 ms，因果才闭合）。**推广：任何"基线/对照/空闲态"断言都要能自证它真的发生在被比较的事件之前，否则就不是基线。**
