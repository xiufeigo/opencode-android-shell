- **中文乱码**：**真因不是字体/编码声明/渲染，而是 `index.html` 被 GBK 往返损坏 156 处** ⇒ 按 `HEAD~1` oracle **逐块恢复**（按 85 / 30 / 0 三类分别归因，**不猜**）。

**P2 的证据强度**：用 **CDP `Page.crash`** 真起崩溃（非源码断言）—— 重建后**零复发**；第 2/3/4/5 次连崩**全落诊断页**。

> ⚠️ **沿用 UX14 的归因纪律**：旧文案说 `onRenderProcessGone` "编译期解析不到" —— **那是类名写错**（真名 `RenderProcessGoneDetail`）。**错误归因比缺口本身更贵**，它让一个 30 行的改动看起来像不可能，于是这个缺口"诚实记为未闭环"地活过好几轮。

## 2. 幻影 saga —— 三代实现，三种失败方式

### 2.1 机制根源（UX14-P4/P5 已钉死，本轮直接复用）

- 4173 条目 = **上游 builtin**，由 `location.origin` 派生、**压根不在 `list` 里** ⇒ 上游 `canRemove` **永不成立**。
- 注册表结构里有 `hidden` 容器，但**上游无任何写入入口**。
- 非 builtin 行（实测 4095）菜单确有 `Remove` ⇒ **4173 不可删是 builtin 属性，不是 UI 缺陷**。

### 2.2 三代实现对照

| 代 | 方案 | 批 | 失败方式 |
|---|---|---|---|
| **v1** | DOM 级隐藏（XPath 扫描 + 条件化闸门） | #7 / #9 | **泛化风险** —— 已两次实证**藏错容器**：`<html>` 整屏全黑；"只剩红点、名字消失" |
| **v2** | DOM 级隐藏（匹配服务器行 + 切换器） | #12 | 🔴 **致命自锁死** |
| **v3** | 注册表 `hidden` 写入 | #11 | 🔴 **上游不消费** —— 写进去了，4173 仍在、也不自动切 |

### 2.3 v2 的自锁死（最有价值的一条，因为它解释了历史）

Home 页头的服务器切换器长这样：

```html
<button aria-haspopup="dialog" data-component="home-projects-dropdown" aria-label="Projects">
  <span><bdi>All projects</bdi><bdi>127.0.0.1:4173</bdi></span>
</button>
```

**这个按钮本身就显示当前服务器名 `127.0.0.1:4173`** ⇒ v2 的隐藏规则**一并命中它** ⇒ **加完服务器后，这个唯一的切换入口被藏掉** ⇒ **切不走、永久 `Loading`**。

🔴 **这一条回溯解释了此前多轮"导航灵异"**（明明加了服务器却仍在 4173、Home 楔死）—— 那些现象不是玄学，是隐藏规则打到了切换器自己。

### 2.4 最终决策（批 #13 落地）

- **不 ship 任何隐藏**；提交 `ac0bb01` 减除 phantom 例程，`PhantomServerHideTest.kt` 一并删除。
- **安全基线 = 4173 始终可见**。
- 🔑 **钉死的机制结论**：**4173 是活跃页面 origin**（页面本身就由 `http://127.0.0.1:4173` 提供）⇒ **入口可以藏、数据源无法改 ⇒ 列表过滤路线不可行**。
- **正确解 = 上游级"活跃上下文重指"**（或让 builtin 可移除）—— **宿主注入层做不到，留档待上游**。

### 2.5 下线后的复验（批 #13）

| 判定 | 结果 | 证据 |
|---|---|---|
| 加服务器不自锁 | ✅ | `home-projects-dropdown` 恢复 `display=flex` / **1017×74** / **无 `data-oc-phantom`**（全文档 count = **0**）；真实 `input tap` 后 `aria-expanded` `false→true`，可列出并切到 4095，**6 个会话正常渲染**，首启永久 `Loading` 未复现 |
| 快速冒烟 | ✅ **4/4** | 终端真 PowerShell 7.6.6 回显 / 发消息得回复 / 后台断 SSE·回前台重建 / 主题 dark |

## 6. 本轮教训（三条，最贵的两条都在"归因"上）

1. **🔴 "看起来稳"可能正是掩盖现场的那层东西。** `reload()` 自愈失败后，60 s 节流让它"稳稳落诊断页"——**若不是坚持追一次真崩溃，这个失败会一直以"已闭环"的样子活着**。
2. **🔴 错误归因比缺口本身更贵。** 旧文案"`onRenderProcessGone` 编译期解析不到"**是类名写错**（真名 `RenderProcessGoneDetail`）⇒ 让 30 行的改动看起来像不可能，于是缺口"诚实记为未闭环"地活过好几轮。本轮中文乱码也是**先猜字体/编码、最后才发现是 GBK 往返损坏 156 处**。
3. **"藏"是最危险的 UI 操作。** v1 藏错容器两次、v2 **直接把唯一的切换入口藏掉导致永久自锁** ⇒ **隐藏类改动必须先问：它命中的是不是那个元素唯一的逃生出口？**
