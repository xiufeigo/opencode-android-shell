- **发现时间**：2026-10-05 20:52（产品负责人实测）
- **产品负责人原话**：
  > 「发现新bug，手机端这个终端界面的 ＋ 应该点了就是直接开终端，而不是弹出这个选项。」
- **现象**：手机档（1200×2670，深色主题）在**终端标签条**上（左侧 `终端 1 ×`，右侧一个 `+`），**点这个 `+` 弹出的是我们那套「打开 / 打开终端 / 打开文件」面板**。
- **应该**：**点它直接新开一个终端**（上游原生行为），**不许弹我们的面板**。
- **根因（待核实，勿照抄）**：我们的拦截**范围抓宽了** —— 命中的不是"审查条/右侧栏那个 `+`"，而是**终端标签条自己的 `+`**。这同时解释了 `UX5_CHOOSER_ACTIONS.md` 里那条"手机档 `+` 锚在终端条"的观察：那不是"等价物"，**是抓错了对象**。
- **上游语义（待给行号证据）**：
  - **终端标签条 `+`** = `terminal.new()` ⇒ **直接新建终端**，必须原样保留；
  - **审查条/右侧栏 `+`** = 打开文件相关 ⇒ 我们才在这里弹面板。
- **修法要求**：
  1. 把"终端条 `+`"与"审查条 `+`"在 **DOM 上的区分**写清楚（选择器/结构原文）；
  2. **收窄拦截范围**：绝不拦截终端标签条的 `+`；
  3. **若手机档根本没有"审查条 `+`"**（UX5 说它桌面限定）⇒ **手机档就不该有任何拦截**，那个 `+` 完全归上游。**必须明确验证并写进报告**。
- **设备证据要求（真实点击）**：
  - 手机档：点终端条 `+` ⇒ 直接出现 `终端 2`（**不再弹面板**），截图 + logcat；
  - 手机档：确认**没有任何位置**还会弹我们的面板（或指出哪一处会、为什么应该）；
  - 平板档：审查条 `+` **仍弹面板**（回归），**且**终端条 `+` 也直接开终端；
  - 顺带回归：终端创建后可用（能敲命令）· 面板配色跟随主题 · 本轮"官方直连 + 删除自定义页"不被改坏。

## B-6 官方「添加服务器」拒绝 http 服务器（提示"无法从 HTTPS 页面连接此 HTTP 服务器"）

- **状态**：**处理中（P0：可能直接挡住产品负责人连自己的服务器）**
- **发现时间**：2026-10-06 09:12（产品负责人实测，手机档）
- **产品负责人原话**：
  > 「**为啥这里显示这个？官方我记得是可以添加 http 的服务器的**」
- **现象**：官方「添加服务器」对话框里，填 `http://8.138.19.15:4094` + 密码 ⇒ 红字报错：
  > **「无法从 HTTPS 页面连接此 HTTP 服务器。请使用 HTTPS 服务器地址。」**
- **✅ 产品负责人已定性（2026-10-06 09:2x，原话）**：
  > 「最初我添加了一个 https 的后端，但是**官方是可以既添加 https 也可以添加 http 的后端的**。所以这个**应该就是你们的 bug**」
  ⇒ **判定：这是我们（壳）的缺陷，不是上游规则**。**必须让它能加 http 服务器**（与官方一致）。
- **架构层面的根因（已能说清）**：
  - **官方桌面端**：外壳**不是"由某台服务器提供的一页"**（Electron 外壳有自己的 origin）⇒ 加服务器**不受当前页面协议约束**；
  - **我们的壳**：形态是**承载"后端自己托管的那一页"** ⇒ **页面协议 = 所配置后端的协议**；产品负责人**先配了 https 后端** ⇒ 这一页变成 https ⇒ **官方那段按 `location.protocol` 的校验就把 http 服务器拒了**。
  ⇒ **这是"承载服务端页面"这一形态带来的约束，需要我们在壳里解决。**
- **修法方向（**先证实判据，再定方案**）**：
  1. **必须先确认上游那条校验的确切判据**：
     - 若是 **`location.protocol === 'https:'`** ⇒ **解法 = 让这一页的来源协议是 http**（例如**重新引入一个"只做 UI 资源服务/转发、绝不接触凭据"的本机 http 来源**，页面从 `http://127.0.0.1:<port>` 加载）；
       ⚠️ **注意**：**UX6 已按产品负责人确认删掉了回环代理** ⇒ 若要走这条路，**必须是"只服务/转发 UI 资源"的最小实现**，**绝不允许重新引入口令注入**（`DirectConnectAuthBoundaryTest` 必须全绿、新代码里 `Authorization`/`password`/`proxy`/`ServerSocket` 必须 0 命中）；
     - 若是 **`window.isSecureContext`** ⇒ ⚠️ **换 http 来源也无效**（**`127.0.0.1` 按规范本身就是 secure context**）⇒ 那就必须**另找上游支持的路径**（例如上游是否有开关/例外），**不许硬绕过**；
  2. **另需核实**：**官方 web 形态（浏览器访问 https 后端）是否也拒 http** —— 若也拒，则说明"这是 web 形态的固有约束、桌面端才有例外"；那就**必须在报告里把这层差异讲清楚**，并给出**壳里可接受的解法**。
- **验收**：**手机档能添加 `http://…` 服务器并真的连上**（截图 + 证据），**且 https 服务器仍能加**（两条都要）。若最终结论是"必须改架构/无法在不碰凭据的前提下做到"，**必须停下并把选项与代价交给产品负责人定**，**不许偷偷把凭据处理加回来**。
- **要查清（给行号原文）**：
  1. **上游那条校验的实现在哪**（`dialog.tsx` 或邻近文件）？**判据到底是什么**（`location.protocol`？`isSecureContext`？还是输入的 URL 与页面协议比较）？**给文件:行号 + 原文**；
  2. **官方在什么条件下允许 http 服务器**（桌面端 Electron 的 origin 是什么？web 端呢？）—— 解释"产品负责人记忆里官方可以"这件事**在什么形态下成立**；
  3. **我们的 APP 里页面实际是什么协议**（设备侧读 `location.protocol` / `location.origin` / `isSecureContext` 的**原文输出**）；
  4. **我们能不能、该不该让 http 服务器可添加**：若上游只按页面协议判断，我们能否（a）让页面以 http 加载（若后端本身是 http），或（b）在 WebView 层允许 mixed content（`setMixedContentMode`），或（c）**这属于上游规则、我们不该绕过** —— **给依据与取舍**。
- **验收**：手机档能按"官方支持的方式"添加服务器并**真的连上**（截图 + 证据）；**若结论是"上游规则如此、不该绕过"** ⇒ **必须给出为什么、以及官方在什么形态下才可以**，并明确告知产品负责人可行路径（例如给他的服务端加 https）。
- **红线**：**不许**为了绕过校验而引入凭据处理，**不许**加回自定义页；改完必须**重建三份产物 + 同步交接文档**。

- **现象**：手机档打开终端面板后，**区域一片空白**（无提示符、无任何输出），**打字没有任何反应**；截图里终端区就是纯黑。
- **对比待查（关键）**：**平板档是否正常？** —— 若平板正常而手机不正常，说明是**手机档特有**（面板为抽屉式/高度或尺寸差异/焦点或软键盘差异），这会大幅缩小根因范围。**必须有对照证据，不许只报手机。**
- **要逐项排查（给行号/原始输出）**：
  1. **面板是否真的连上了 PTY**：`/api/pty/{id}/connect` 是否发起了、返回什么（**注意**：本轮正在改"去掉回环代理、官方直连"，**来源/认证路径变了 ⇒ PTY 连接可能因此受影响**，这条要重点看）；
  2. **xterm.js 是否在渲染**：终端容器**高度是不是 0**、canvas 是否被隐藏、我们的 CSS/注入是否影响了它；
  3. **输入是否到达终端**：终端内的输入元素（通常是个 `textarea`）能否聚焦、软键盘弹出时是否被顶掉、`keydown` 是否被上游键位机制或宿主吞掉（**与 B-2 同源嫌疑**）；
  4. **手机档的终端面板形态**（抽屉/全屏）与高度的取值来源。
- **修复要求**：手机档打开终端 ⇒ **能看到提示符、能敲命令、有回显**；**用真实点击 + 真实按键**取证（截图 + logcat 原文），**修复前后对比**；**并回归平板档不许变坏**。
- **绊线 + 反向验证**：至少一条可断言量（例如"终端面板必须成功建立连接"或"终端容器高度不得为 0"），**撤回修复必须真红**。
